### 勤務実績・警告・打刻の更新

勤務実績は月間予定の達成リング、実績と残り時間、本日・勤務日数・有給取得・今月の平日の指標、PJ別の積み上げバーと個別バーを表示します。有給は年度期間、平日数は「土日・祝日を除く」を添えます。Aの生成り・紺・青緑の書体と配色を引き継ぎ、Aの左上の名称は「SET」とします。

出退勤を入力した後の実働がマイナスでも保存を拒否せず、符号付きの時間を日別・週次・月次に表示します。保存後の警告は7秒間のトーストで表示し、画面内に警告欄を追加しません。操作や入力フォーカスを妨げず、自動で消えます。退勤前は暫定実働を0以上で表示し、出勤直後に予定休憩を引いたマイナス警告を出しません。出退勤が揃った記録の時刻・休憩・工数を変更した場合だけ警告し、作業内容だけの保存では繰り返し表示しません。確定実働がマイナスの間は工数との合計一致を保存条件にしません。不正な時刻や入力範囲、保存失敗の検証は維持しています。Excelでは負の時間を文字列で出力し、Excelの負の時刻表示による文字化けを避けます。

出退勤の保存成功時だけ、同じサイズのボタンでチェック描画・短いバウンド・光の通過を表示し、850ms後に通常表示へ戻します。保存失敗時には成功表示を出しません。動きを減らす設定では動かさずチェックを表示します。

### 勤怠一覧からの日別編集

日付の編集はダイアログではなく、Aデザインの専用画面です。前日・翌日・カレンダーで日付を選び、出社時間・退社時間・休憩時間（hh:mm）・自動計算の勤務時間・休日設定・勤務場所・作業内容・P1〜P4/SETの順で入力します。休憩は候補の選択と分単位の手入力に対応します。工数の合計が実働に一致すると「振り分け完了」と表示します。更新後も同じ日の編集画面に留まり、保存結果をトーストで表示します。日付の切替やタブ移動では更新前の入力を画面内で保持し、未来の日付は選べません。勤怠一覧・ホーム・提出確認へ戻る操作も用意しています。

### デバッグと操作改善

- ホームの打刻・手入力・休憩修正と、勤怠の日別編集で、出退勤が揃った時点の実働をP1へ自動反映します。手動のP2〜P4・SETは残し、P1は「実働−他PJの合計」を分単位で計算します。他PJだけで実働を超えた場合はP1を0とし、既存の工数を消さず不一致を案内します。負の工数は自動入力しません。
- 工数を手動入力した場合は自動処理で上書きせず、合計一致を検証します。退勤前は一致を要求しないため、工数0のままでも、出勤後に仮の工数を入れた状態でも日別編集を保存できます。退勤未入力は提出時に止めます。ホームの未保存の工数は未保存のまま保持し、更新ボタンで保存します。
- ホームの休暇入力の「更新」ボタンは右寄せに配置します。
- 勤務場所・作業内容の保存に失敗しても入力を保持し、「未保存」「再保存」を表示します。ホームの工数・休暇・休憩の入力中の値は、画面内の切替で保持します。これらの未保存値はブラウザを閉じる前に保存してください。
- 日別編集から戻ると、元の月と一覧のスクロール位置を復元します。ブラウザの戻る／進むでアプリ内の画面を移動できます。
- 工数・設定の数値欄は必須入力とし、空欄を意図せず0で保存することを防ぎます。未入力の工数を振り分け完了と表示しません。
- モバイルの入力欄は16px以上、日付移動は44px以上のタップ領域にし、固定ナビを避けるスクロール余白を追加しました。Aの配色・書体・項目順は維持しています。
- 勤務中の今週グラフは毎分更新します。休暇日のExcelに初期休憩や勤務場所を出力せず、出力処理が失敗した場合は提出済みの履歴を残しません。
- 初月のサンプルが不正な時刻にならないようにし、同じ値の重複保存で警告が消える問題も防止しました。

回帰テスト：`node tests/paper-attendance-check.cjs`。ブラウザの回帰テストはPlaywright/Chromiumを用意して `node tests/paper-ui-check.cjs`（必要に応じて `PAPER_PLAYWRIGHT_MODULE` と `PAPER_CHROMIUM_PATH` を指定）。新しい失敗例、入力・フォーカス保持、ナビゲーション、出力失敗、モバイルの文字サイズとタップ領域を実際の画面イベントで確認しています。Chromiumのスマホ表示で確認しており、iPhone実機のSafariでの最終確認は未実施です。

### 提出時のチェック

提出する期間の今日までの記録を検証します。平日の未入力・退勤未入力も提出を止めます。全日の休暇は勤務時間の検証対象から除きます。

- 平日の実働が0〜4時間の場合、有休または半休の登録を促します。午前・午後の半休を登録済みならこの短時間チェックを免除します。土日・公式祝日の休日出勤は短時間でも有休を要求せず、作業内容・工数・マイナス実働などの検証は行います。
- 勤務実績がある日の「作業内容」（日別の作業概要）が未入力、または空白だけの場合は提出できません。設定画面の共通の作業概要では代用しません。
- 実働とP1〜P4・SETの工数合計を分単位で比較し、不一致なら提出できません。未配分の0も対象です。
- マイナス実働は保存できますが、半休の有無にかかわらず提出を止めます。
- 確認画面に日付と理由をまとめ、対象日から編集画面へ進めます。提出ボタンの無効化に加え、出力処理の `prepareSubmission` でも同じ検証を実行し、失敗時はExcel生成と履歴登録を行いません。別画面で保存内容が変更された場合も提出を止めます。

勤怠タブの月別Excelは確認用の出力として残し、提出の検証とは分けています。実際のメール送信やサーバーは未接続であり、ここでの処理側の検証はブラウザ内です。実送信を接続する場合は送信先でも同じ条件を検証する必要があります。

回帰テスト：`node tests/paper-submission-check.cjs`、Playwright環境の `node tests/paper-submission-ui-check.cjs`。4時間の境界、半休、空白だけの作業内容、工数不一致、マイナス実働、ボタンを強制的に有効にしても提出できないこと、修正後の出力・履歴、打刻時のP1配分を確認します。

### 代休と元の休日出勤日

ホームの「休暇」と勤怠タブの日別編集の「休日設定」で「代休」を選び、表示される元日の欄から休日出勤日を選択します。1日の休日出勤に対し1日の代休を紐付け、半日ずつの分割には対応しません。

候補は記録開始日以降、代休日より前、今日までの土日または公式祝日で、出退勤が揃い実働が正の記録です。会社独自の休日カレンダーは未導入です。同じ元日を他の代休に使うことはできません。候補がなければ、先に休日出勤の記録を登録する案内を表示します。

代休は全日休暇として未入力チェックから除外し、有給取得数には含めません。元日の取消・削除や、正の実働がなくなる変更は、紐付けを解除するまで保存できません。代休を通常勤務や他の休暇へ変更すると元日の利用を解除します。元日の変更時は、代休日を含む提出履歴も未提出へ戻します。提出処理でも元日の存在・休日勤務実績・前後関係・重複利用を再検証します。Excelの勤務表には「代休元の休日出勤日」列を追加します。

既存の保存データは `sourceDay` がなくても読み込めます。代休のリンクが不正でもデータ全体を破棄せず、保存や提出時の検証で修正を案内します。

追加の回帰テスト：`node tests/paper-batch-check.cjs` とPlaywright環境の `node tests/paper-batch-ui-check.cjs`。勤務中の保存、両画面の自動配分と手動配分保持、代休登録・重複・元記録の変更、提出処理の再検証とモバイル表示を確認します。

`.github/workflows/paper-checks.yml` はAの関連ファイルが変更されたときに、6本のモデルテストと7本のChromiumテストを実行します。ブラウザ用ツールは一時フォルダへ入れ、サイト本体への依存追加はしません。公開前の検証には `codex/paper-batch9` ブランチを使います。

### 月ごとの勤務予定

基本の勤務予定は、その月全体の平日数（土日・公式祝日を除く）×8時間で自動計算します。2026年10月は21日×8＝168時間、11月は19日×8＝152時間です。有休・代休の取得で基本値を自動減算することはありません。

ホームの勤務実績にある「勤務予定」の「変更」から、勤務予定だけを保存する専用フォームを開きます。自動計算中でも数字を直接入力でき、入力した時点でその月の手動指定に切り替わります。「保存」で反映し、「自動計算に戻す」で基本値を選び直せます。設定画面の他の必須項目や、未保存の設定入力には左右されません。

「設定」→「勤務表設定値」の勤務予定も直接入力できます。自動／手動の選択は残しますが、自動計算中の数値欄を無効化しません。指定できる時間は0〜744時間です。明示した0は保存し、空欄を0として保存しません。祝日未収録月の自動計算は値を空にして保存でき、手動指定の空欄とは区別します。

手動の値は `settings.plannedHoursByMonth` に年月ごとに保存し、ほかの月へ持ち越しません。自動へ戻すとその月の指定だけを削除します。勤務実績の達成率・残り時間と毎秒の更新にも、同じ月の予定を使用します。祝日データがない月は基本値を推測せず「—」とし、手動指定を利用できます。

旧データの固定168時間は自動計算へ移行し、以前に168以外へ変更していた値は移行時の月の手動指定として保持します。打刻・休暇・工数・提出履歴は移行処理で変更しません。

追加の回帰テスト：`node tests/paper-planning-check.cjs`、Playwright環境の `node tests/paper-planning-ui-check.cjs`。月跨ぎ・祝日・手動指定の保存と自動への復帰、0と空欄、旧データ移行、進捗リング・残り時間、モバイルの横はみ出しを確認します。

### デモと実利用準備用の分離

`paper-config.js` がHTMLの `data-app-mode` に従って初期状態と保存先を選びます。URLパラメーターでは切り替えません。既存のデモの保存先は維持し、実利用準備用への自動コピー・移行・消去は行いません。

実利用準備用は `mode: "local"`、`settings.attendanceStartDay`、`settings.employee`（name / department / id）を持つ空の初期状態を作ります。氏名等が未設定でも架空社員へ置き換えません。初期設定・PJ・場所には取引先のサンプル情報を入れず、勤怠一覧や未入力チェックは利用開始日以降を対象にします。開始前の行は編集不可とし、Excelにも開始前であることを表示します。サンプル切り替えや固定時計は実利用準備用では動作しません。

既存のデモデータはそのまま読み込めます。読み込み失敗・破損・モード違いの場合は保存を停止し、元の内容を上書きせず、架空の履歴を代わりに表示しません。初回表示だけでは保存先に書き込みません。

### 保存処理の接続口

`paper-app.js` は保存先へ直接アクセスせず、`paper-repository.js` の非同期インターフェースを使用します。画面は読み込み・保存の完了を待ち、保存前の成功表示や、処理中の重複打刻を防ぎます。保存中に書き足した作業内容も下書きとして保持します。

| メソッド | 動作 |
| --- | --- |
| `load()` | 初期状態または保存済みデータのコピーを返す。初期状態を自動保存しない。 |
| `save(next, { expectedRevision })` | 更新番号を照合して保存し、新しいコピーを返す。更新番号は保存側で進める。 |
| `assertCurrent(expectedRevision)` | 変更がないことを、提出や同値保存の前に確認する。 |
| `subscribe(listener)` | 別画面での変更を通知し、購読解除用の関数を返す。自動で未保存入力を置き換えない。 |

現在の実装は `PaperRepository.createLocal(options)` です。将来は同じインターフェースを持つアダプターを `window.PaperRepositoryFactory` に指定して差し替えます。AWS・DynamoDB・Microsoft 365ログイン・実際のAPI通信は今回追加していません。

保存側は読み込み時の生データと更新番号の両方を照合し、同じ更新番号のまま別画面が書き換えた場合も上書きを防ぎます。保存が失敗した場合は、元データと更新番号を維持します。エラーコードは `conflict` / `storage_unavailable` / `invalid_data` / `not_ready` です。

追加の回帰テスト：`node tests/paper-initialization-check.cjs`、`node tests/paper-repository-check.cjs`、Playwright環境の `node tests/paper-preparation-ui-check.cjs`。初期化と開始日・社員・Excel、データ分離、破損時の保護、非同期の完了前後、保存失敗・競合、モバイル表示を確認します。

### 月ごとの欠勤時間

1日8時間を基準に、記録済みの平日の不足分を分単位で合計します。実働は休憩を引いた時間、午前・午後の半休は4時間分として計算し、実働4時間＋半休なら欠勤時間は0です。別の日の残業で不足分を相殺せず、月の勤務予定を手動変更しても1日の基準は8時間を保ちます。

全日の有給・公休・特別休暇・代休、土日・公式祝日、未来日・利用開始前は除きます。未入力日、半休だけで打刻がない日、退勤未入力は欠勤時間に含めず、既存の未入力確認で扱います。確定実働が負の場合は0時間として不足分を計算し、マイナス実働の警告と提出不可の扱いは維持します。祝日データ未収録の平日は欠勤判定を行いません。

ホームの勤務実績、勤怠タブの月集計、日別編集で確認できます。記録を保存した際の不足案内はトーストで表示し、画面内の警告欄は増やしません。出勤直後や退勤前には不足のトーストを出しません。8時間未満だけを理由に保存や提出を止めることはなく、既存の4時間以下・作業内容・工数・マイナス実働の提出チェックは維持します。

回帰テスト：`node tests/paper-absence-check.cjs`、Playwright環境の `node tests/paper-absence-ui-check.cjs`。日ごとの不足と月集計、半休・全休・休日・未入力・勤務中・月境界、保存と警告、モバイル表示を確認します。

### ホームから休憩を1タップで変更

ホームの休憩欄に0・30・45・60・90分のボタンを常時表示し、選ぶとその日の休憩時間を保存します。標準の初期値は60分（1時間）です。保存済みの値を選択状態で表示し、設定済みの初期休憩や過去の記録は上書きしません。細かい分数は従来の時間・分の入力欄から保存できます。

変更後は実働・P1への自動配分・欠勤時間を更新し、手動のP2〜P4・SETと他の入力下書きは保持します。保存中は連打を防ぎ、失敗した場合は元の選択と入力内容を維持します。勤務中は不足の警告を出さず、出退勤がそろった記録の警告は既存のトーストで表示します。Playwright環境の `node tests/paper-rest-ui-check.cjs` で、1タップ保存と再読み込み、細かい休憩の入力、保存失敗・非同期保存、集計・工数・下書き保持、スマホの操作領域を確認します。

### 勤務予定とプロジェクト設定の入力

勤務予定を「平日数 × 8時間（自動）」にしているときも、下の時間欄を編集すると即座に「時間を指定（この月のみ）」へ切り替えます。入力イベントを発生させない自動入力も、設定の保存・項目や画面の切り替え時に変更分を保持します。自動計算へ戻す操作と、未保存の手動入力を行き来する動作も維持します。

プロジェクトの情報はP1〜P4とSETの5件です。5つ目の枠がSETです。各プロジェクトをボタンで選び、名前・略称と担当作業を入力します。ボタンには名前と未保存の印を表示し、前後のプロジェクトにも移動できます。切り替え時は入力中の勤務予定・場所・他のプロジェクトの値を保ち、画面下の「更新」でまとめて保存します。不備のあるプロジェクトは対象を表示し、入力欄へ移動します。

工数もP1〜P4とSETの5枠に統一します。従来の4件だけのプロジェクト設定にはSETの情報をメモリー上で補います。変更途中のP5とSETが分かれている保存データでは、5件目の名前・概要をSETへ引き継ぎ、P5とSETの工数を分単位で合算して総工数を保持します。読み込みだけでは保存内容・更新番号・提出履歴を変更せず、次の明示的な保存で反映します。保存・再読み込みを繰り返しても重複加算しません。画面・集計・提出時の検証・ExcelはSETを5枠目として扱い、左上のSET表記も維持します。

回帰テスト：`node tests/paper-projects-check.cjs`、Playwright環境の `node tests/paper-settings-ui-check.cjs`。既存データの読み込みと保存、5枠目のSET・提出・Excel、変更途中の6枠からの合算、勤務予定の切り替え、5件の下書きと入力不備、スマホでの配置を確認します。

合算した既存のSETが通常の24時間上限を超える場合は、元のP5・SET配分を `legacyProjectAllocation` に保持します。元の各値が0〜24時間の分単位で、合算値と一致する場合だけ既存値を保持できます。通常の新規入力の上限は24時間のままです。不正な値や欠損した保存データを0で補って隠すことはありません。
